# ADC 诊疗管理系统 · 本地版

安德鲁牙科连锁（ADC）的诊所管理演示系统。六个角色、一条完整业务链，
双击 `run.bat` 就能在自己电脑上跑起来，**不需要装任何东西**（只要 Python 3.10+）。

> 当前状态：**可演示、可走通全流程**。7 轮独立验收累计查出 60 余条问题，
> 其中影响「钱算错、数据写坏、越权、500 卡死」的已全部修完并回归；
> 13 个自检脚本 + 3 个交付校验全绿。尚未经过真实诊所试用，见文末「已知限制」。
>
> **另有一个患者端小程序**（`miniprogram/`，10 个页面 + 14 个 JSON 接口），
> 在微信开发者工具模拟器和手机真机上都已跑通，说明见 `小程序-操作说明.md`。

## 一、怎么启动

1. 确认电脑装了 Python 3.10 或更高版本（命令行敲 `python --version` 能看到版本号）。
2. 双击 `run.bat`。
3. 浏览器打开 <http://127.0.0.1:8000>。

第一次启动会自动建库、灌演示数据（约 10 秒），之后再启动就直接进。
数据存在 `data/adc.db` 一个文件里，想重来就把它删掉再跑一次 `run.bat`。

> 如果双击闪一下就没了，说明没找到 Python。在命令行里执行
> `python --version` 看是否报错；没有的话去 python.org 装一个（安装时勾选
> "Add Python to PATH"）。

## 三、六个角色分别能干什么

### 患者
- 选门店 → 选日期（每天标出还剩几个号）→ 选时段 → **确认页**（选给谁看、留电话、写来意）→ 拿到预约编号
- 改约（可以换门店，原店的号会释放）、取消（要选原因）、看就诊记录和账单、看通知

### 前台
- 今日队列：每条「已预约」有四个动作——登记到诊 / 改约 / 登记爽约 / 取消
- 代客预约（帮打电话来的患者约）、散客挂号（没预约直接来的）
- 患者检索、查病历

### 牙医
- 今日诊台（只列自己的号）、写病历（主诉/现病史/检查所见/诊断/处置）、
  登记治疗项目（牙位、数量、单价）、登记影像资料、开结算单

### 助手
- 耗材领用（扣库存、写流水、可挂到某次就诊上）、低于补货点的物料提醒

### 店长
- 本店看板（今日预约、待审批、待处理投诉）、排班（新建/停诊/恢复/改容量）、
  请假审批（批准会真的把那几天的排班停掉并取消预约、发通知）、
  调班审批、投诉处理（要填处理结果）、业绩

### 总部运营
- 全连锁看板、门店管理、跨店征调审批、质量事件登记与闭环、
  账号管理（重置口令/停用/改角色）、审计日志、证照到期预警、数据状态
- **采购 → 收货入库 → 对账 → 挂应付**、库存总览/批次/盘点/调拨

### 财务
- 结算单列表与详情、收款、**退费与红冲**、日结对账、经营报表、
  供应商对账、应付账款与付款

## 四、业务链是怎么串起来的

```
患者在线预约  ──→  前台登记到诊  ──→  牙医写病历、加治疗项目
                                          │
                                          ↓
                                   前台/财务开结算单
                                          │
                            ┌─────────────┴─────────────┐
                            ↓                           ↓
                       患者在线支付                 前台收现金
                            │                           │
                            └─────────────┬─────────────┘
                                          ↓
                                    收款记录（可退费冲回）
                                          ↓
                                     日结对账 / 经营报表

耗材：采购单 → 收货入库（生成批次、加库存、写流水）
     → 助手领用（扣库存、写流水）→ 盘点（改账套、写差额）
     → 跨店调拨（同事务写两条流水）
     → 对账 → 挂应付 → 付款
```

## 五、几个设计上的取舍（评审时值得讲）

- **状态按金额派生，不读状态字段**：结算单「已收款/部分收款/待收款」、应付单
  「已付清/部分付款/未付款」都是现算的，不是存着的一个字段。避免了
  「状态说已收、金额说没收」这种自相矛盾。
- **退费写成负向收款**：不新建退费表，`PAYMENT` 里记一条金额为负的记录，
  「已收」本来就是 `SUM(amount)`，天然抵掉。
- **盘点、调拨不建新表**：写成 `STOCK_MOVEMENT` 的新类型。这样
  「账套现值 = 流水净额」这条对账关系一直成立（每个账套还有一条「期初」流水）。
- **预约状态机**：只有「已预约」能流转，已到诊/已取消/爽约都是终态。
- **占号口径只写一次**：`OCCUPIED` 常量，全站 11 处共用，避免「页面说剩 0、
  接口还能约进去」。
- **乐观锁**：`version_no` 列 + 修改时校验，防止两个人同时改同一张单。

## 六、技术栈

- Python 3.10+ **标准库**：`http.server` + `sqlite3`，**零第三方依赖**
- 页面是服务端拼字符串（f-string），CSS 手写内联，没有前端框架
- 口令 PBKDF2-SHA256 加盐，会话存 `SESSION` 表，HttpOnly Cookie
- 数据库 58 张表，脚本 `app/schema.sql` 建表，`tools/seed*.py` 灌数据

```bat
cd code

python _e2e.py              :: 主链路 21 项
python _stage2_check.py     :: 预约状态机 7 项
python _stage3_check.py     :: 号源与排班 5 项
python _stage4_check.py     :: 回访/账号/质量/日结/导出 16 项
python _stage5_check.py     :: 并发到诊与开单 5 项
python _stage6_check.py     :: 权限与看板口径 14 项
python _stage7_check.py     :: 采购到付款 21 项
python _stage8_check.py     :: 库存批次/盘点/调拨 17 项
python _stage9_check.py     :: 并发扣减与数值边界 4 项
python _stage10_check.py    :: 作废/跨店改约/导航/待办 30 项
python _final_acceptance.py :: 最终验收 31 项（业务链/交接/一致性/权限/异常）
python tools\_audit.py      :: 静态体检
python tools\_scan_all.py   :: 全站五类扫描
python tools\_chk_stock.py  :: 库存账实一致
python tools\_chk_over.py   :: 号源不超订
python tools\_fresh_check.py:: 干净目录从零建库
```

合计 **17 个脚本、约 180 项自动检查**，全绿才算能交。

其中 `_final_acceptance.py` 是最后加的那一层，它不看「页面能不能打开」，
而看「一个真实用户能不能把业务流程走完」：预约→到诊→病历→开单→收款→退费
走一遍、牙医写的东西患者能不能看到、应收=明细、已收=收款-退费、库存=流水、
报表对得上账面、七个角色进不该进的页面会不会被拦、不存在的编号是不是 404。

## 八、已知限制（别当生产系统用）

- **单进程 SQLite**：适合一台电脑几个人用，不适合多人高并发。真上线要换
  PostgreSQL/MySQL 并加连接池。
- **没有 HTTPS、没有 CSRF token、没有登录失败限流**：只在本机 `127.0.0.1` 跑，
  不要直接暴露到公网。
- **没有做过压力测试**：一家店一天几十个号没问题，三千条预约同时查会不会慢，
  没测。SQLite 单写者，真多人同时用会排队。
- **跨店改约只做到「换门店重选时段」**：可以先选门店再挑时段，但没有「保留原号
  同时占新号」的两阶段提交。
- **在线支付是模拟的**：`PAYMENT` 记一笔就完了，没接微信/支付宝。
- **影像只登记引用**：记「存放在哪」，不做文件上传（本地没有对象存储）。
- **短信/微信通知没接**：站内通知表 `NOTICE` 有，患者登录能看到。
- **演示数据是随机生成的**：金额、日期、姓名都是假的，不要拿它当经营参考。
- **报表口径**：运营费用是 2026Q4 整季、收入覆盖 2026-10-12 至 11-12，两者期间
  不一致，页面上已经标注了这一点。
- **没有多语言、没有移动端适配**。
- **在线支付、短信、影像上传都是模拟或引用**，不是真的对外接口。
- **没有压力测试**：一家店一天几十个号没问题，三千条预约同时查会不会变慢没有实测过。
- **作废的范围有限**：结算单可以整张作废（没收过钱时），但改成已收款就得先退费；
  采购单、应付账单没有作废入口，只能靠冲正记录抵。加工过的就诊记录不能删。

## 九、出问题了怎么办

- **端口被占**：命令行 `netstat -ano | findstr :8000` 看谁占着，
  或者换个端口：`python app\server.py --port 8010`（也可以用环境变量 `ADC_PORT=8010`）。
- **想用另一个数据库文件**：设环境变量 `ADC_DB=D:\某处\test.db`。
- **改了代码不生效**：很可能是旧进程还占着 8000。用 `tools\restart.ps1` 重启，
  它会先把占端口的进程杀掉。
- **数据乱了想重来**：删掉 `data\adc.db`，再跑一次 `run.bat`。
